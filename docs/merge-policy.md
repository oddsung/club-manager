# 머지 정책 — 리드 자동 머지 (B안 + 기계 관문)

> 2026-11-04 사람 결정: **B안** — 조건을 만족하면 리드(코디네이터)가 사람 요청 없이 PR을 머지하고, worktree도 정리한다.
> 같은 날 사람 결정: 매번 사람 승인 없이 머지. 단, **조건 확인은 리드의 말이 아니라 `scripts/agent-merge.mjs`가 강제**한다.
> (사이클 3에서 리드·팀원의 보고가 세션 기록과 달랐음 → "규칙은 부탁, 검사는 강제")

## 머지 방법 — 이것만 허용
```
node scripts/agent-merge.mjs <PR 번호>            # 검사 통과 시 머지 + PR에 검사 결과 댓글
node scripts/agent-merge.mjs <PR 번호> --dry-run  # 검사만
```
- `gh pr merge`, `gh api .../merge` 직접 실행은 **금지**(`.claude/settings.json` deny)
- 검사한 커밋(sha)으로만 머지되므로, 검사 뒤 새 커밋이 올라오면 GitHub가 거부한다
- 스크립트가 거부하면 **우회하지 말고** 사람에게 PR 번호와 ❌ 항목을 보고한다

## 스크립트가 강제하는 조건 (모두 충족)
| 항목 | 내용 |
|---|---|
| 기본 | 열려 있는(초안 아님) `agent/*` → `main` PR |
| P1 CI | head 커밋의 check run 전부 성공, `check` 포함 |
| P2 크기 | 코드·테스트 변경 500줄 이하 |
| P3 배정 파일만 | `main`의 `docs/tasks/` 배정 표에서 브랜치 이름(`agent/<팀원>`)과 같은 팀원 줄의 파일 안에서만 변경 |
| P4 | `src/`를 바꾸면 `tests/` 변경도 있어야 함 |
| 기존 테스트 | 기존 테스트 파일은 **추가만** 허용 (수정·삭제가 있으면 사람) |
| 사람 전용 파일 | `.claude/`, `.github/`, `scripts/`, `AGENTS.md`, `CLAUDE.md`, `package*.json`, 설정 파일 → 사람 |
| 결정 문서 | `docs/` 중 `progress.md`, `lessons.md`, **TASK 지시서의 `> 상태:` 줄만 바꾼 변경** 외(요구사항, 정책, 로드맵, TASK 내용, 매니저 지침) → 사람 |

## 리드가 머지 전에 스스로 확인하고 보고서에 적는 조건 (기계 검사 불가)
1. 병렬 작업이면, 같은 사이클 PR을 모두 합친 통합 worktree에서 `npm run check` 통과
2. 팀원이 `/verify` 형식으로 완료 보고
3. 팀원이 확정 사항과 다르게 해석한 부분이 있으면, 그 해석을 사람이 확인함

## 사람이 머지하는 PR
- 스크립트가 거부한 PR 전부 (위 "사람 전용 파일", "결정 문서", 기존 테스트 수정 포함)
- 의존성 추가가 들어간 PR (`package*.json` 이 바뀌므로 자동으로 거부됨)

## 머지 후 정리 (리드가 승인 없이)
```
git worktree remove .worktrees/<이름>     # --force 금지: 커밋 안 된 변경이 있으면 git이 거부 → 사람에게 보고
git worktree prune
git branch -d agent/<이름>                 # -D 금지: 머지 안 된 브랜치면 git이 거부
```

## 감사와 기록
- 스크립트는 검사 결과를 PR 댓글로 남긴다. 매니저(`docs/manager.md`)가 정기 실행 때 리드가 머지한 PR을 다시 검사해 #27에 기록한다
- 리드는 머지한 PR 번호와 위 1~3을 어떻게 확인했는지를 최종 보고와 `docs/progress.md`에 남긴다
- 사이클 기록(`docs/lessons.md`)에서 리드가 한 머지·정리는 사람 개입으로 세지 않는다
- 이 정책과 스크립트 변경은 사람이 PR로 리뷰·머지한다
