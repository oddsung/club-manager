# 머지 정책 — 리드 조건부 머지 (B안)

> 2026-11-04 사람 결정: **B안** — 아래 조건을 모두 만족하면 리드(코디네이터)가 사람 요청 없이 PR을 머지한다.
> 3단계 "자동 승인 정책 문서화"의 첫 항목. 조건 중 하나라도 어긋나면 머지하지 않고 사람에게 보고한다.

## 리드가 머지해도 되는 조건 (모두 충족)
1. CI `check` 가 성공했다 (`gh pr view <번호> --json statusCheckRollup` 로 확인)
2. 변경 파일이 작업 지시서에서 그 팀원에게 배정한 파일 안에만 있다 (`gh pr view <번호> --json files` 로 확인)
3. 병렬 작업이면, 같은 사이클의 PR을 모두 합친 상태에서 `npm run check` 가 통과했다 (통합 worktree)
4. 팀원이 `/verify` 형식으로 완료를 보고했다
5. 팀원이 확정 사항과 다르게 해석한 부분이 있으면, 그 해석을 사람이 확인했다 (예: TASK-005 Q13 `""` 처리)

## 리드가 머지하지 않는 PR (사람이 머지)
- 단계 판정·정책·요구사항 확정처럼 **사람의 결정을 기록하는 docs PR** — 머지가 곧 사람의 확정이다
- `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.github/`, `package.json`, `eslint.config.js`, `tsconfig.json` 을 바꾸는 PR
- 기존 테스트를 고치거나 지운 PR (PR 설명에 이유가 있어도 사람이 본다)
- 의존성 추가가 들어간 PR

결과 기록·진행 상황처럼 결정이 없는 docs PR은 CI 통과만 확인하고 리드가 머지해도 된다.

## 머지 방법
- 한 번에 하나씩: `gh pr merge <번호> --merge`
- 다른 명령과 `&&` 로 잇지 않는다 (TASK-005에서 묶은 명령이 auto 모드 분류기에 차단됨)
- `--delete-branch`, `--squash`, `--rebase`, `--admin` 은 쓰지 않는다
- 차단되거나 실패하면 우회하지 말고 사람에게 보고한다

## 기록
- 머지한 PR 번호와, 조건 1~5를 어떻게 확인했는지를 최종 보고와 `docs/progress.md` 에 남긴다
- 사이클 기록(`docs/lessons.md`)에서는 리드가 한 머지를 사람 개입으로 세지 않는다
