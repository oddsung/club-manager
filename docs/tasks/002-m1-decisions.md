# TASK-002 — M1 확정 사항 반영 (Q1~Q7)

> 상태: 완료

> 이 파일 내용을 그대로 Claude Code 세션에 붙여 넣어 시작합니다.

## 목표
`docs/requirements.md`의 R-01, R-03에 **"(Qn 확정)"** 으로 표시된 항목을 구현에 반영한다.
현재 구현과 이미 같은 항목(Q2, Q3, Q4, Q7)은 그 동작을 지키는 테스트가 있는지만 확인한다.

## 진행 방식 (중요 — 이번 사이클의 확인 대상)
1. **코드를 고치기 전에** 이 작업을 몇 개의 PR로 나눌지 계획을 짧게 보고하고 승인을 기다린다.
   - 원칙: PR 하나는 목적 하나, 코드·테스트 변경 500줄 이하 (CI 크기 검사)
2. 승인된 계획대로 PR을 하나씩 만든다. 각 PR은 독립적으로 `npm run check`를 통과해야 한다.
3. 앞 PR이 머지되기 전에 다음 PR을 시작해야 하면, 다음 브랜치를 앞 브랜치가 아니라 `main` 기준으로 만들 수 있게 PR 순서를 설계한다.

## 완료 조건 (모두 충족해야 완료)
1. 모든 PR에서 `npm run check` 통과, CI(크기 검사 포함) 통과
2. Q1: 재활성화 동작과 "이미 활성인 회원 재활성화 시 오류"를 테스트로 증명
3. Q5: 팀 수 1 이하이면 오류 — 테스트로 증명. 기존 테스트 중 팀 수 1을 쓰던 것이 있으면 의도에 맞게 수정하고 PR 설명에 적는다
4. Q6: 균형 기준 대기 선정
   - 대기 인원이 있는 입력에서, **무작위 선정(기존 방식)보다 spread가 나빠지지 않음**을 테스트로 증명
     (같은 입력에서 이전 방식과 비교하거나, 소규모 입력에서 완전탐색 최적값과 비교)
   - 같은 시드 → 같은 결과 유지
   - 기존 균형 기준(하드 상한, 실용 기준, 최적성) 테스트가 그대로 통과
5. Q2, Q3, Q4, Q7: 해당 동작을 지키는 테스트가 있는지 확인하고, 없으면 추가
6. 각 PR 설명에 어떤 Qn을 다뤘는지 적는다
7. 마지막에 `/verify` 형식으로 전체 결과를 보고한다

## 보고에 포함할 증거
- PR 목록 (번호, 다룬 Qn, 변경 줄 수)
- Q6 알고리즘 변경 한 줄 설명과, "나빠지지 않음"을 무엇으로 증명했는지

- 외부 런타임 의존성 추가 금지

- 작업 브랜치: `agent/<짧은-설명>` (PR마다 하나)
