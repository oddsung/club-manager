# TASK-006 — 최근 모임 연속 결석 회원 조회 (R-11)

> 상태: 대기

> 출처: 이슈 #32

> 이 파일 내용을 그대로 Claude Code 세션(리드)에 붙여 넣어 시작합니다.

## 목표
`docs/requirements.md` 의 **R-11 최근 모임 결석 회원 조회**를 구현하고 테스트한다.
총무가 연락할 회원을 찾기 위해, 최근 N회(기본 3회) 지난 모임에 한 번도 출석하지 않은 활성 회원 목록을 돌려준다.

## 당신의 역할
당신은 **코디네이터(리드)** 입니다. `AGENTS.md` "팀 작업" 규칙을 따르고, 직접 코드를 쓰지 않습니다.

## 배정
| 팀원 | 요구사항 | 만들 파일 (이 파일만) |
|---|---|---|
| `absentees` | R-11 (R11-1 ~ R11-8) | `src/absentees.ts`, `tests/absentees.test.ts` |

- 기존 `src/attendance.ts`, `src/meetings.ts`, `src/members.ts`, `src/index.ts` 는 **수정하지 않고** import 해서 조합만 한다
- 의존은 필요한 메서드만 `Pick<...>` 으로 받는다 (예: `Pick<MemberRegistry, "list">`, `Pick<MeetingBoard, "list">`, `Pick<AttendanceBook, "isChecked">`)
- 테스트 픽스처는 가짜 이름만 사용한다
- 예상 변경: 200줄 이하 (팀원 1명이므로 병렬 없음)
- 요구사항과 다르게 해석될 여지가 있으면 구현 전에 리드에게 메시지로 묻는다

## 진행 방식
1. 리드는 위 배정 그대로 진행한다는 **한 줄 계획**을 사람에게 보고하고 승인을 기다린다
2. 승인되면 팀원 1명을 띄운다. spawn 프롬프트에 반드시 포함:
   - R-11 규칙 번호, 만들 파일, worktree·브랜치 이름(`agent/absentees`)
   - **`AGENTS.md` "팀 작업"의 명령 형식 표에 있는 명령만 사용. `cd`와 `&&` 연결 금지.** 표에 없는 명령은 실행 전에 리드에게 메시지
   - **완료 전에 `/verify` 스킬을 실행하고 그 보고 형식으로 리드에게 보고**
3. PR이 올라오면 통합 점검(`npm run check` 통과, 배정된 파일만 변경)
4. `docs/merge-policy.md` 에 따라 `node scripts/agent-merge.mjs <PR 번호>` 로 머지 → worktree 정리
5. `/verify` 형식으로 보고

## 완료 조건
1. PR 1개, CI 통과, `src/absentees.ts`·`tests/absentees.test.ts` 만 변경
2. R11-1 ~ R11-8 각 규칙을 지키는 테스트가 있음 (테스트 이름이나 주석에 규칙 번호 표시)
3. 도메인 코드에서 `Date.now()`·인자 없는 `new Date()` 를 쓰지 않음 (현재 시각은 `now` 주입)
4. 리드는 `src/`, `tests/` 를 직접 수정하지 않음

## 보고에 포함할 것
- PR 번호, 변경 줄 수, R11-n 별 테스트 이름
- 팀원이 문서에 없어 스스로 정한 부분 (있으면 목록 — 매니저가 `docs/requirements.md` "논의 중"에 옮김)
- **팀 운영 기록 (사실과 추정을 구분)**: 표에 없는 명령 시도, 리드에게 온 메시지, 팀원이 `/verify`를 실행했다고 보고했는지

## 제약
- 새 패키지 추가 금지
- 연락처 출력은 범위 밖 (회원 정보에 연락처 없음 — "논의 중" 유지)
- 가입일·활성 이력은 저장하지 않으므로 새로 만들지 않는다 (R11-5 한계 그대로)
