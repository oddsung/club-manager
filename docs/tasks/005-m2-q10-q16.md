# TASK-005 — M2-Q10~Q16 확정 사항 반영 (병렬 사이클)

> 상태: 완료

> 이 파일 내용을 그대로 Claude Code 세션(리드)에 붙여 넣어 시작합니다.

## 목표
`docs/requirements.md` "TASK-004 경계값 테스트 중 나온 질문"의 확정 7건을 구현·테스트에 반영한다.
- **[변경]** Q10, Q13, Q16: 실패하는 테스트로 먼저 현재 동작을 드러낸 뒤 `src/`를 고친다 (AGENTS.md 버그 수정 규칙)
- **[유지]** Q11, Q12, Q14, Q15: 코드는 그대로 두고, 그 동작을 지키는 테스트만 추가한다

## 환경 검증 포인트 (이번 사이클의 확인 대상)
- TASK-004에 이어 **휴대폰만으로** 끝나는지 (사람 승인은 계획 승인 1회가 목표)
- 팀원이 이번에는 `src/`를 고친다 — 배정된 파일 밖을 건드리지 않는지
- 팀원이 완료 전에 `/verify` 를 실행하는지 (TASK-004에서 2명이 생략)

## 당신의 역할
당신은 **코디네이터(리드)** 입니다. `AGENTS.md` "팀 작업" 규칙을 따르고, 직접 코드를 쓰지 않습니다.

## 배정
| 팀원 | 다룰 Qn | 고칠 파일 (이 파일만) |
|---|---|---|
| `fix-dues` | Q10 [변경], Q11 [유지] | `src/dues.ts`, `tests/dues.edge.test.ts` |
| `fix-attendance` | Q13 [변경], Q12 [유지] | `src/attendance.ts`, `tests/attendance.edge.test.ts` |
| `fix-meetings` | Q16 [변경], Q14·Q15 [유지] | `src/meetings.ts`, `tests/meetings.edge.test.ts` |

- 기존 테스트가 새 규칙과 충돌하면(예: Q16) 그 테스트를 **삭제·skip 하지 말고** 새 규칙에 맞게 고친 뒤 PR 설명에 이유를 적는다
- 확정 내용과 다르게 해석될 여지가 있으면 구현 전에 리드에게 메시지로 묻는다

## 진행 방식
1. 리드는 위 배정 그대로 진행한다는 **한 줄 계획**을 사람에게 보고하고 승인을 기다린다
2. 승인되면 팀원 3명을 띄운다. spawn 프롬프트에 반드시 포함:
   - 다룰 Qn, 고칠 파일, worktree·브랜치 이름(`agent/<팀원 이름>`)
   - **`AGENTS.md` "팀 작업"의 명령 형식 표에 있는 명령만 사용. `cd`와 `&&` 연결 금지.** 표에 없는 명령은 실행 전에 리드에게 메시지
   - [변경] 항목은 "실패 테스트 먼저 → 수정" 순서
   - **완료 전에 `/verify` 스킬을 실행하고 그 보고 형식으로 리드에게 보고**
3. PR 3개가 올라오면 통합 점검(합쳐서 충돌 없음, `npm run check` 통과)
4. 팀원 종료 후 `/verify` 형식으로 보고

## 완료 조건
1. PR 3개, 각각 CI 통과, 각 PR은 배정된 파일만 변경
2. Q10·Q13·Q16: 수정 전 실패했던 테스트가 수정 후 통과 (PR 설명에 적기)
3. Q11·Q12·Q14·Q15: 해당 동작을 지키는 테스트가 있음
4. 합친 상태에서 충돌 없음, `npm run check` 통과
5. 리드는 `src/`, `tests/` 를 직접 수정하지 않음
