# TASK-003 — M2 병렬 구현 (2단계: 코디네이터 + 에이전트 팀)

> 상태: 완료

> 이 파일 내용을 그대로 Claude Code 세션(리드)에 붙여 넣어 시작합니다.

## 당신의 역할
당신은 이 작업의 **코디네이터(리드)** 입니다. `AGENTS.md`의 "팀 작업" 규칙을 따릅니다.
**직접 코드를 쓰지 않습니다.** 팀원을 띄워 일을 나누고, 결과를 점검하고, 사람에게 보고합니다.

## 목표
`docs/requirements.md`의 **M2 초안(R-04, R-05, R-06)** 을 팀원 3명이 **동시에** 구현해 PR 3개를 만든다.

## 진행 방식
1. 구현 시작 전에 사람에게 **짧은 계획**을 보고하고 승인을 기다린다
   - 팀원 3명의 이름, 각자 맡을 요구사항·파일·브랜치 (예: `attendance` → R-04, `src/attendance.ts`, `tests/attendance.test.ts`, `agent/attendance`)
   - 요구사항 초안에서 구현 전에 사람이 정해야 할 모호한 점이 있으면 함께 질문
2. 승인되면 **에이전트 팀**으로 팀원 3명을 띄운다 (서브에이전트가 아니라 teammate로).
   각 팀원의 spawn 프롬프트에 다음을 포함한다
   - 맡은 요구사항 ID, 만들 파일, 브랜치/worktree 이름
   - `AGENTS.md` "팀 작업"의 worktree 절차를 따를 것
   - 완료 = 자기 worktree에서 `npm run check` 통과 + push + PR 생성, PR 번호를 리드에게 보고
3. 팀원이 일하는 동안 리드는 기다린다. **팀원 대신 구현하지 않는다**
4. 팀원 질문은 리드가 받아, 요구사항 문서로 답이 되면 답하고, 아니면 사람에게 묻는다
5. PR 3개가 모두 올라오면 **통합 점검**을 한다
   - 세 브랜치를 임시로 합쳐도 충돌이 없는지, 합친 상태에서 `npm run check` 통과하는지
   - 서로 파일을 침범하지 않았는지, M1 파일이 바뀌지 않았는지
6. 팀원을 종료시키고 `/verify` 형식으로 보고한다

## 완료 조건
1. PR 3개, 각각 CI 통과 (크기 검사 포함)
2. 세 PR을 합친 상태에서 충돌 없음, `npm run check` 통과
3. 각 PR이 맡은 요구사항의 규칙마다 테스트를 가진다
4. 리드는 `src/`, `tests/` 를 직접 수정하지 않았다

## 보고에 포함할 것 (환경 검증용 — 중요)
- PR 목록 (번호, 팀원, 요구사항, 변경 줄 수)
- 통합 점검 결과
- **팀 운영 기록**: 팀원별로 막힌 지점, 리드에게 온 질문, 권한 승인이 필요했던 명령
- 리드가 직접 개입해야 했던 일이 있었다면 무엇이고 왜였는지
