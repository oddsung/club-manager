# 에이전트 관리 환경 로드맵

> 이 레포의 목적은 앱 자체가 아니라 **AI 코딩 에이전트 관리 환경**을 검증하는 것입니다.
> 동호회 앱은 각 단계를 시험하는 작업 부하입니다. 집에서 검증한 뒤 회사(GitLab CE, 사내망)에 이식합니다.

## 매 단계 공통 지표
| 지표 | 목표 |
|---|---|
| 작업(PR) 1건당 사람 개입 횟수 (승인·답변·재지시) | 단계가 올라가도 늘지 않거나 줄어든다 |
| 개입 1회의 무게 | "push 승인" 같은 가벼운 개입 위주 |
| 검사(CI·lint)가 막은 실수 비율 | 사람 눈보다 검사가 먼저 잡는다 |
| `main`에 들어간 규칙 위반 | 0 |

기록은 `docs/lessons.md`의 사이클 기록표에 남깁니다.

## 진행 순서 (2026-11-05 사람 결정)
**3단계 통과 → 3.5단계 Paseo 비교 → 3.6단계 M3 화면 검증 → 4단계 회사 이식 (+ 템플릿화)**

## 1단계 — 신뢰 레이어 ✅ 통과 (2026-11-04)
- 구성: `AGENTS.md`/`CLAUDE.md`, `.claude/settings.json` 권한, `npm run check`, CI(크기 검사 포함), `main` 보호 규칙(PR·CI 필수), verify 스킬
- 근거: 사이클 1~2에서 PR당 개입 약 3.5회 → 약 1회, 실수→검사 승격 1회(PR 크기 검사)

## 2단계 — 코디네이터 (병렬화) ✅ 통과 (2026-11-04, 사이클 4·5 재검증 — 머지로 사람 확정)
- 근거: 사이클 4·5 연속 팀원 3명 병렬 PR 모두 CI 통과·충돌 없음, 사람 개입은 리드 쪽 계획 승인 1회 + 판단 확인. 남은 과제: 머지 주체 정책
- 구성: 직접 코딩하지 않는 코디네이터 세션 1개 + 워커 여러 개. 사람은 코디네이터와만 대화
- 트랙 A (주 트랙, 회사 이식 가능): 집 PC의 Claude Code 에이전트 팀 + Remote Control
- 트랙 B (비교용): Claude Code Projects (클라우드 스레드, GitHub 전용)
- 통과 기준: 워커 3개 이상이 동시에 서로 다른 PR을 만들고 모두 CI 통과, 충돌 없음, 사람 개입은 코디네이터 쪽에서만, PR당 개입 1회 수준 유지

## 3.5단계 — Paseo 비교 사이클 (3단계 통과 후, 2026-11-04 사람 결정)
- 목적: 관제 도구를 Claude Code(Remote Control + 에이전트 팀)에서 **Paseo**(셀프 호스팅 데몬 + 모바일 앱)로 바꿨을 때 차이 확인. 4단계(회사 이식) 도구 선택 근거
- 방법: 같은 성격의 TASK 하나를 Paseo로 실행 (worktree·병렬·폰 승인), 규칙 파일·CI·머지 관문은 그대로
- 비교 항목
  | 항목 | 확인할 것 |
  |---|---|
  | 사람 개입 | 같은 지표(PR당 개입, PC 화면 필요 여부)로 비교 |
  | 승인 경로 | **팀원(병렬 에이전트)의 권한 요청도 폰으로 오는가** (사이클 3 문제) |
  | 다중 도구 | Claude Code 외 에이전트(Codex 등)를 같은 규칙으로 섞어 쓸 수 있는가 |
  | 보안 경계 | 데몬 접속 경로(Tailscale·내부망), 자격 증명 위치, 외부 노출 여부 |
  | 운영 부담 | 데몬 설치·업데이트·재시작, Windows 지원 |
  | 라이선스 | AGPL-3.0 — 회사 내부 사용 조건 확인 |

## 3.6단계 — M3 화면 검증 (Paseo 비교 후, 2026-11-05 사람 결정)
- 목적: 화면(입력·클릭)이 있는 프로그램도 같은 환경으로 "검사가 강제하는" 개발이 되는지 확인. 회사 프로그램(RPA 앱, 도면 관리 등) 대부분이 화면을 가지므로 4단계 전에 검증
- 제품 쪽: 동호회 앱 **M3 웹 화면** — 회원 목록, 출석 체크, 팀 편성 (스택·범위는 매니저가 이슈로 질문해 확정)
- 환경 쪽
  | 층 | 내용 | 관문 여부 |
  |---|---|---|
  | ① 자동 E2E | Playwright로 입력·클릭·결과 확인 → `npm run check`와 CI에 포함 | **머지 관문** |
  | ② 에이전트 실사용 확인 | `/verify` 확장: 앱을 띄워 직접 조작, 화면 변경 PR은 스크린샷 첨부 필수 | 증거 (PR 첨부) |
  | ③ 사람의 눈 | (선택) PR별 미리보기 배포 링크를 폰으로 확인 | 디자인·사용성 판단 |
- 머지 정책: 처음엔 **화면을 바꾼 PR은 사람 확인 후 머지**(머지 관문 스크립트에 화면 경로 추가) → E2E가 안정되면 리드 자동 머지로 전환
- 통과 기준: E2E가 CI에서 매번 같은 결과로 통과, 화면 PR에 스크린샷 첨부, 사람 개입이 3단계 수준 유지

## 4단계 — 보안 점검과 회사 이식
- GitHub → GitLab CE, GitHub Actions → GitLab CI, 접속 경계를 사내망에 맞춤, AI 거버넌스 정책 대조
- 3.5단계(관제 도구), 3.6단계(화면 검증) 결과를 반영해 도구·검증 방식 선택
- 다른 프로젝트 적용을 위한 **템플릿 레포** 정리 (프로젝트별 신뢰 레이어는 1단계부터 다시 쌓음)
- 결과물: 회사 적용 체크리스트, 템플릿 레포
