# 요구사항 — 운동 동호회 관리 프로그램

> 요구사항은 대화하며 확정된 것만 여기에 추가합니다. 에이전트는 여기 없는 기능을 추측해서 만들지 않습니다.
> 각 요구사항은 ID(R-xx)로 참조합니다. 구현 범위는 "현재 마일스톤"에 적힌 것만입니다.

## 제품 비전
- 배드민턴, 족구, 배구, 축구 등 **여러 종목**의 동호회가 함께 쓸 수 있는 회원관리 앱/웹
- 사용자: 운영진(회장, 총무 등)과 일반 회원
- 장기적으로 동호회 인원 규모에 따른 유료 기능 적용 고려 (지금은 설계·구현 대상 아님)

## 현재 마일스톤 — M1: 도메인 로직 (화면·DB·인증 없음)
목표: 순수 TypeScript 도메인 로직과 테스트만으로 R-01~R-03의 핵심 규칙을 구현한다.
저장은 메모리 내 구조로 충분하다. UI, DB, 네트워크, 인증은 M1 범위가 아니다.

### R-01 회원 관리 (M1 범위)
- 회원 등록: 이름(필수), 실력 등급(필수)
- 회원마다 고유 ID 부여
- 회원 조회(ID), 목록 조회, 정보 수정, 탈퇴(비활성화) 처리
- 비활성 회원은 팀 편성 대상에서 제외

### R-02 실력 등급 (M1 범위)
- 등급은 정수 점수로 표현 (높을수록 실력이 좋음)
- 종목별로 등급 체계가 다를 수 있으므로 **등급 체계는 설정값으로 주입**한다 (예: 1~5, 또는 A~D를 점수로 매핑)
- 회원의 등급 변경 가능

### R-03 팀 자동 편성 (M1 범위)
- 입력: 당일 참석 회원 목록, 팀 수, 팀당 인원수
- 출력: 팀 목록 (각 팀의 회원과 등급 합계)
- 규칙
  - 각 팀의 등급 합계 차이가 가능한 한 작아야 한다 (실력 균형)
  - 같은 입력이라도 실행할 때마다 구성이 달라질 수 있어야 한다 (무작위성)
  - 테스트를 위해 **난수 시드를 주입**할 수 있어야 한다 (같은 시드 → 같은 결과)
  - 참석 인원이 `팀 수 × 팀당 인원수`보다 적으면 오류
  - 참석 인원이 더 많으면 남는 인원은 "대기" 목록으로 반환
- 종목 독립적이어야 한다 (배드민턴 복식 2명, 족구 4명, 배구 6명, 축구 11명 등 모두 같은 로직)
