## 제품 비전

- 사용자: 운영진(회장, 총무 등)과 일반 회원
- 장기적으로 동호회 인원 규모에 따른 유료 기능 적용 고려 (지금은 설계·구현 대상 아님)

## 현재 마일스톤 — M1: 도메인 로직 (화면·DB·인증 없음)
목표: 순수 TypeScript 도메인 로직과 테스트만으로 R-01~R-03의 핵심 규칙을 구현한다.
저장은 메모리 내 구조로 충분하다. UI, DB, 네트워크, 인증은 M1 범위가 아니다.

### R-01 회원 관리 (M1 범위)
- 회원 등록: 이름(필수), 실력 등급(필수)
- 회원마다 고유 ID 부여
- 회원 조회(ID), 목록 조회, 정보 수정, 탈퇴(비활성화) 처리
- 비활성 회원은 팀 편성 대상에서 제외
- (Q1 확정) 비활성 회원을 **재활성화**할 수 있다. 이미 활성인 회원을 재활성화하면 오류
- (Q2 확정) 비활성 회원도 정보·등급을 수정할 수 있다
- (Q3 확정) 회원 ID는 저장소 내 순번(`m-1`, `m-2` …)을 유지한다. 저장 방식(DB) 결정 시 재검토

### R-02 실력 등급 (M1 범위)
- 등급은 정수 점수로 표현 (높을수록 실력이 좋음)
- 종목별로 등급 체계가 다를 수 있으므로 **등급 체계는 설정값으로 주입**한다 (예: 1~5, 또는 A~D를 점수로 매핑)
- 회원의 등급 변경 가능
- (Q7 확정) 회원 등급은 **점수**로 저장하고, 라벨(A~D 등)은 등급 체계로 변환해 표시한다

### R-03 팀 자동 편성 (M1 범위)
- 입력: 당일 참석 회원 목록, 팀 수, 팀당 인원수
- 출력: 팀 목록 (각 팀의 회원과 등급 합계)
- 규칙
  - 각 팀의 등급 합계 차이가 가능한 한 작아야 한다 (실력 균형)
  - 같은 입력이라도 실행할 때마다 구성이 달라질 수 있어야 한다 (무작위성)
  - 테스트를 위해 **난수 시드를 주입**할 수 있어야 한다 (같은 시드 → 같은 결과)
  - 참석 인원이 `팀 수 × 팀당 인원수`보다 적으면 오류
  - 참석 인원이 더 많으면 남는 인원은 "대기" 목록으로 반환
  - (Q4 확정) 참석 목록에 같은 회원이 중복되면 오류
  - (Q5 확정) 팀 수는 **2 이상**이어야 한다. 1 이하이면 오류
  - (Q6 확정) 대기 인원은 **팀 균형이 가장 좋아지도록** 고른다 (무작위 선정 아님)
    - 출전 인원 전체를 균형 기준으로 고르고, 나머지가 대기가 된다
    - 균형이 같은 후보가 여럿이면 시드 기반 무작위로 고른다 (같은 시드 → 같은 결과 유지)
    - 알려진 단점: 특정 등급의 회원이 반복해서 대기로 빠질 수 있음 → R-04(출석) 이후 순번제와 함께 재검토
- 종목 독립적이어야 한다 (배드민턴 복식 2명, 족구 4명, 배구 6명, 축구 11명 등 모두 같은 로직)

## 마일스톤 — M2: 출석 · 회비 · 일정 (도메인 로직) — 완료 (PR #11~#13)
> 2026-11-04 기본안으로 작성한 **초안**입니다. 사람이 PR 리뷰에서 수정·확정합니다.
> M1과 같이 화면·DB·인증 없이 순수 TypeScript 도메인 로직과 테스트만 만듭니다.
> 세 기능은 **서로 다른 파일**에서 독립적으로 구현합니다 (2단계 병렬 작업 검증용).

### 공통 규칙 (M2)
- 회원은 M1의 `Member`(id, active)를 참조만 한다. M1 파일(`members.ts`, `teams.ts` 등)은 수정하지 않는다
- **현재 시각은 인자(`now: Date`)로 주입**한다. 도메인 코드에서 `Date.now()`, 인자 없는 `new Date()` 금지 (lint가 막음)
- 모임은 문자열 ID(`meetingId`)로만 참조한다. R-04는 R-06 모듈에 의존하지 않는다
- 금액은 원 단위 정수, 날짜 비교는 주입된 시각 기준
- `src/index.ts` 는 수정하지 않는다 (파일 충돌 방지). 테스트는 각 모듈을 직접 import 한다

### R-04 출석 체크 → `src/attendance.ts`
- 모임(meetingId) 단위로 회원 출석을 체크하고, 체크를 취소할 수 있다
- 같은 모임에 같은 회원을 두 번 체크하면 오류, 체크되지 않은 회원을 취소하면 오류
- 비활성 회원은 출석 체크할 수 없다 (오류)
- 모임별 출석자 목록을 조회할 수 있다 → 그대로 R-03 팀 편성의 참석자 목록으로 쓸 수 있는 형태
- 회원별 출석 이력(모임 ID 목록)과 출석률(주어진 모임 ID 목록 중 출석한 비율)을 계산할 수 있다

### R-05 회비 납부 → `src/dues.ts`
- 월 회비는 동호회 설정값(정액, 원 단위 정수)으로 주입한다
- 회원별로 회비 면제를 지정·해제할 수 있다
- 납부 기록: 회원, 대상 월(`YYYY-MM`), 금액, 납부 시각(주입). 금액은 월 회비와 같아야 한다 (부분 납부 없음)
- 같은 회원·같은 월 중복 납부는 오류
- 월별 미납자 목록: 해당 월 기준 활성 회원 중 면제가 아니고 납부 기록이 없는 회원
- 월별 납부 합계를 조회할 수 있다

### R-06 모임 일정 공지 → `src/meetings.ts`
- 모임 생성: 제목, 시작 일시, 장소(선택), 메모(선택), 응답 마감 일시(선택). 고유 ID 부여
- 모임 수정, 취소(취소된 모임은 목록에서 구분 가능)
- 다가오는 모임 목록: 주입된 현재 시각 이후 시작, 취소 제외, 시작 시각 순
- 회원별 참석 응답: 참석 / 불참 / 미정. 응답 변경 가능
- 응답 마감 이후 응답·변경은 오류. 취소된 모임에 응답하면 오류. 비활성 회원은 응답 불가
- 응답 집계: 참석·불참·미정 인원 수와 각 회원 목록
