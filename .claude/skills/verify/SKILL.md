# verify — 완료 증명 절차

"완료"는 주장이 아니라 증거입니다. 아래 순서를 모두 수행하고 결과를 보고에 포함하세요.

1. `git status` 와 `git diff --stat` 로 변경 범위를 확인합니다.
   - 요청과 무관한 파일이 바뀌었다면 되돌리거나, 왜 필요한지 설명합니다.
2. `make check` 를 실행합니다.
   - 실패하면 완료가 아닙니다. 원인을 고친 뒤 다시 실행합니다.
   - 테스트를 지우거나 skip 처리해서 통과시키지 않습니다.
3. 새 기능/버그 수정이라면, 그것을 검증하는 테스트가 추가되었는지 확인합니다.
4. `docs/requirements.md` 의 해당 요구사항과 구현이 일치하는지 대조합니다.
5. 이번 작업에서 같은 실수를 두 번 이상 했다면 `docs/lessons.md` 에 한 줄 기록합니다.

## 보고 형식 (휴대폰에서 읽기 좋게 짧게)

```
✅/❌ make check: <통과/실패>
변경: <파일 수>개 — <한 줄 요약>
테스트: <추가/수정한 테스트 한 줄>
남은 일/확인 필요: <없으면 "없음">
```
